## What's in this release

The first build that is actually **iNWEB** — real Chromium at the pinned
baseline (never a WebView, §71) with the Stage-2 patch series applied:

| Patches | What lands |
|---|---|
| `ui/0001–0004` | App identity: launcher name "iNWEB" (ADR-038), package `com.inweb.android`, iNWEB in-app strings, launcher icons, themed app icon |
| `adblock/0005–0007`, `0012` | Filter engine: rule parsing + matching (RE2), tracking-protection engine, URL-loader throttle wired into the network stack, per-frame cosmetic CSS injection |
| `popup/0008–0011` | Popup/redirect guard, redirect throttle, notification-policy quieting, engine-backed download guard |

Verified on the artifact itself, not asserted:

- `AndroidManifest.xml` package = `com.inweb.android`
- `res/mipmap-xxxhdpi-v4/app_icon` is **byte-identical** to the icon
  patch `0003` installs (sha256 `ec1b2abc…`), not the pristine Chrome icon
- `resources.arsc` carries 423 iNWEB strings (10,586 upstream "Chrome"
  strings remain — only brand-bearing strings are renamed)

## What this is NOT (honest boundaries)

- **A development build** (`is_debug = true`, `symbol_level = 1`), signed
  with the default debug keystore. It is **not** an official/release
  build, and it is not security-audited.
- **No in-place upgrade path to a future official build.** Different
  signing key from any future release build → a later official install is
  a fresh install, not an update. Same for alpha.1 (package
  `org.chromium.chrome`): this is a **fresh install**, not an upgrade.
- **No extension support.** Even though the registry/permission-review
  core exists, extensions are not enabled — patches `0014`–`0017` have
  not landed, so browsing the Web Store is just browsing (§16).
- **No offline pages / data saver / reader mode** (patches `0018`–`0020`
  not landed). The data-saver decision core is authored and unit-tested
  but not wired into the browser.
- **No security-center or settings patches** (`0021`–`0025`). The Home Page
  app-layer probe, later assigned `0013`, was still in progress with the
  project's UI/UX developer at this release point.
- **No adult-content blocker yet** (scheduled as `0026`).
- **No device-matrix verdict.** B-1…B-4 are automatic and pass; the
  device rows B-5…B-8 and the G-closure remain **pending** — this release
  has not been installed on any device by the project.

## Known issues

- `chrome_public_apk__lint` reports two `UnusedResources` warnings for the
  generated RTL pseudo-locale (`values-ar-rXB`) copies of
  `fre_activity_label` and `search_widget_description` — both strings that
  patch `0002` renames. Upstream baselines these as unused in the real
  locales but has no pseudo-locale entries; they are accepted through
  `chrome/android/expectations/lint-suppressions.xml` with a written
  rationale (lint runs with `--warnings-as-errors`).
- Issue #1 (open): upstream has moved to `154.0.8037.49`; this build stays
  on the pinned `.21` baseline by policy (ADR-001).

## Install / upgrade notes

- **Fresh install only.** Package `com.inweb.android`; uninstall any
  earlier iNWEB/Chromium test build first if Android complains about the
  signing key.
- Target ABI: `arm64-v8a`. Minimum Android: whatever the pinned Chromium
  baseline requires (Android 10+ / API 29+ target in the build config).
- Debug-signed: `adb install -r` works, Play Protect will warn on a
  debug-signed APK — expected for a development-channel artifact.
