## What this is

The **pristine upstream Chromium Android stable build** at the pinned
baseline `154.0.8037.21`, produced by the project's own GitHub-hosted,
resumable Actions build chain (hop 14 = run 35715711786; full ledger:
[`../verification/B001-BUILD-CHAIN.md`](../verification/B001-BUILD-CHAIN.md)).
No iNWEB patches are applied — this is the honest engine baseline required
before any iNWEB modification is built (B-001 gate).

- Real Chromium engine: `lib/arm64-v8a/libchrome.so` 468.5 MB, 11 `classes.dex`
- Locales: `bn.pak` + `en.pak` present
- arm64-v8a target
- Integrity: the sha256 was computed on the runner, re-computed on the
  downloaded Actions artifact, and re-verified on the published release
  asset — identical at every hop (bit-for-bit chain).

## What this is NOT

- **Not iNWEB-branded**: label "Chromium", package `org.chromium.chrome`
  (the iNWEB identity — name, package `com.inweb.android`, logo — arrives
  with the Stage-2 patch series in the next release).
- **No iNWEB features**: no tracking protection, adblock, popup protection,
  or iNWEB UI modifications.
- Not a security-audited product release; it is a development-channel
  baseline artifact.

## Field notes (author device — anecdotal, not the formal B-5 verdict)

Installed and used interactively by the author on a Xiaomi Redmi 15
(Android 16 / HyperOS, Snapdragon 685, 8 GB RAM): install, launch,
networking, rendering and input all worked in real use, including a full
interactive chat session conducted inside the browser; Bengali text rendered
correctly. Recorded as device-matrix data point #1 (§48); the formal
B-5…B-8 matrix remains pending.

## Install / upgrade policy

This is the one-time **fresh install** baseline. The first iNWEB-branded
release (`v1.0.0-alpha.2`, package `com.inweb.android`) installs alongside —
a package-id change — after which all subsequent updates are in-place over
the same package id and signing key (user data preserved).
