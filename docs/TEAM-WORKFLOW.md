# iNWEB Browser — Team Workflow & Ownership

**Status:** active from 2026-09-25 (project directive).
**Roles:** Lead Developer (build/CI agent) · Junior Developer (Home Page UI/UX).

This document exists because the Home Page work runs **in parallel with a
live, real-Chromium build chain**. A stray edit in the wrong file can cost
a 30–40 minute build hop or, worse, produce a tree that no longer matches
the patch series. The boundaries below are the control that prevents that.

---

## 1. Ownership map

| Path | Owner | Notes |
|---|---|---|
| `iNWEB_PATCHES/**`, `iNWEB_PATCHES/MANIFEST.yaml` | **Lead** | The single authority for the Chromium tree (ADR-001/040). Never hand-edit. |
| `src/native/**` (C++: adblock, popup, extensions, offline) | **Lead** | Authoring sources the patches are generated from. |
| `scripts/**` (apply_patches, native_harness, validators) | **Lead** | CI gates live here. |
| `.github/workflows/**` | **Lead** | ci-authoring, b001-verify, b001-build-hop, upstream-watch. |
| `src/core/**` (existing modules) | **Lead** | 11 modules, 414 Kotlin tests. |
| **`src/core/home/**` (new)** | **Junior** | Pure-JVM Home Page logic + its tests. New module, nothing existing to break. |
| `docs/design/inweb-prototype/**` | **Junior** | Interactive prototype + design handoff (see §4). |
| `docs/MASTER-SPEC.md`, `PROJECT_STATE.md`, ADR-relevant docs | **Lead** | Spec/state are single-writer. |
| Anything under a Chromium path (`chrome/...`) | **Lead** | Does not exist in this repo; ships only as a patch entry. |

**Hard rule for the Junior:** do not edit anything in the Lead column. If a
Home Page change seems to require it, stop and raise it — the Lead will
make the change or generate the patch.

## 2. Conflict avoidance

1. One owner per file (table above). No exceptions without an explicit
   handover recorded in this document.
2. The Junior works on a branch: `feature/home-<topic>` (existing:
   `feature/home-prototype`). Nothing is pushed to `main` by the Junior.
3. This repository has **no pull-request workflow** (0 PRs to date). The
   Lead reviews by diffing the branch (`compare/main...<branch>`), then
   lands the work on `main` personally after review.
4. Before the Junior starts a file that might overlap with an in-flight
   Lead change (e.g. shared theme/string resources), the Lead declares the
   file "in use" in this document's §5 status table.

## 3. Review & integration protocol (Lead's side)

When the Junior signals "Home Page ready", the Lead runs, in order:

1. `compare/main...feature/home-*` — verify **only** Junior-owned paths
   changed; every other touched path is a blocker.
2. `bash scripts/validate_kotlin_core.sh` — all modules, 414+ tests green
   (the Junior's new tests included).
3. `python3 -m unittest discover -s tests -t .` — 80 Python tests.
4. `bash scripts/validate_strings.py` / `validate_localization.py` — every
   user-visible string externalized, no hardcoded UI text.
5. `python3 scripts/lint_manifest.py` and
   `python3 scripts/apply_patches.py verify <tree>` — patch series intact.
6. Architecture review against the checklist in
   [`HOME-PAGE-HANDOFF.md`](HOME-PAGE-HANDOFF.md) §6 (no WebView, honesty
   of claims, counters, accessibility, no core-file drift).
7. Only then: generate/refresh the patch entry, run `b001-verify` +
   `ci-authoring`, and land on `main`.

Integration instructions for the Junior are issued after step 6 — not
before — so they reflect the code that actually exists.

## 4. Decision authority

Architectural decisions are the Lead's (project directive #7). Standing
decisions for the Home Page work:

- **D1 — Logic lives in `src/core/home`.** Home Page behaviour (search
  routing, shortcut/bookmark/recent-page models, privacy-status state,
  widget/card configuration) is a pure-JVM module with unit tests, exactly
  like `tracking-protection` and `offline`. The Android view layer is a
  thin renderer over it.
- **D2 — Chromium-tree code ships as a patch.** Anything under
  `chrome/android/java/**` becomes patch entry **`ui/0026-home-page`**
  generated by the Lead (0025 stays reserved for the adult-content
  blocker). The Junior never authors patch files.
- **D3 — Design source of truth** is `docs/design/inweb-prototype/`
  (`DESIGN-HANDOFF.md`, `DESIGN-TOKENS.json`, `NAVIGATION-SPEC.md`,
  `INTERACTION-STATE-SPEC.md`, `VISUAL-QA-CHECKLIST.md`). Where the
  prototype and MASTER-SPEC §38 disagree, §38 wins and the mismatch is
  raised, not silently resolved.
- **D4 — No PRs.** Branch → Lead diff review → Lead lands on `main`.
- **D5 — No core-file edits** for Home Page convenience (directive #5).
