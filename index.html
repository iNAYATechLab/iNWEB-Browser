Features

Everything a modern browser should be.

Core modules are implemented and covered by unit tests before they ship — quality is part of the architecture, not an afterthought.

Real Chromium engine

Compiled from the upstream Chromium source (pinned stable baseline) — the genuine Brave / Vivaldi / Kiwi class. Never Android WebView.

Ad & tracker blocking

EasyList-family filter engine with cosmetic filtering, per-site allowlists, and a combined URL matcher verified 165–259× faster.

Extensions

A full extension lifecycle — install, review, enable/disable, update with consent, remove — with recorded permission reviews.

Offline library

Save pages for later with real byte quotas, LRU eviction, pinned favorites and atomic storage — no phantom offline files.

Privacy by default

Tracking protection is on from the first launch, with a Security Center model and clear per-site statistics.

Built for the long run

A tracked 24-patch series on pinned upstream tags keeps our changes reviewable and rebase-friendly — no giant unmaintainable fork.

Architectural identity

WebView wrapper vs. real Chromium-derived.

Most "browsers" on the store are a thin skin over Android's WebView. iNWEB Browser belongs to a different category entirely.

Typical wrapper WebView shell

  • Rebranded system WebView (Chromium-lite, frozen features)
  • Engine updates depend on the device's OS version
  • Limited rendering control, weak privacy guarantees
  • Cannot ship real Chromium features (flags, extensions, network stack)

iNWEB Browser Chromium source build

  • Full Chromium source — pinned upstream stable  154.0.8037.21
  • Engine evolves on our schedule via tracked patch overlay (ADR-001)
  • Deep privacy modifications at the engine level — not site scripts
  • Material 3 app layer in Kotlin, unit-tested core modules

FAQ

Common questions

Is iNWEB Browser just another WebView wrapper? ▾
No — and this is the project's non-negotiable architectural identity. It is compiled from the upstream Chromium source code with a tracked patch series, exactly like Brave, Vivaldi or Kiwi. The engine is never Android WebView, and no build step is allowed to turn it into one.
Is the ad blocker a real filter engine? ▾
Yes. It parses EasyList-family filter lists, supports cosmetic filtering, per-site allowlists and statistics, and uses a combined URL matcher that is equivalence-verified to be 165–259× faster than naive matching. Filter lists are cached with SHA-256 content pinning.
When is the stable version coming? ▾
The project is in Stage 2 (patch-series authoring) of its roadmap, with 4 of 24 patches complete and the engine baseline already shipped as alpha. Watch the repository or follow the releases page to catch new builds early.
How can I contribute or report a bug? ▾
Head to the GitHub repository — open an issue for bugs or ideas. For security-sensitive reports, please use GitHub's private vulnerability reporting instead of a public issue.
